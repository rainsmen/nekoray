# nekoray 项目与代码评估报告（当前状态版）

> **评估日期**：2026-08-23
> **评估基线**：`HEAD=115e4d6`（`5.0.0-beta.4`）+ 当前工作区未提交改动。
> **评估方式**：静态审查代码、构建脚本、GitHub Actions、依赖声明、测试与文档。
> **工具链限制**：当前环境已使用临时 Go 1.22 工具链执行 Go 测试；没有 Dart/Flutter，因此未执行 Flutter analyze/test。
> **状态约定**：`Confirmed`=源码可直接证明；`Partial`=部分修复或仍有残留；`Needs verification`=需要工具链/运行环境；`Fixed`=当前源码已覆盖原问题。

## 1. 综合结论

当前项目架构方向正确：Flutter UI + Go/sing-box core + localhost gRPC，模块边界清楚，已有鉴权、更新包 SHA-256、原子写入、规则集路径防护、基础单元测试和移动/桌面 CI。

当前不宜直接作为稳定版发布，主要原因不是原报告中已经修复的 N1/N2/P0 旧问题，而是以下仍开放的发布风险：

- updater 已先 staging 校验并提供备份/失败恢复；仍需工具链验证异常路径；
- Windows 父进程监督已改为句柄等待，但仍需 Windows 实机验证；
- macOS updater 与 Intel/Apple Silicon 打包已接入，但仍需 CI 产物验证；
- Update Check/Download 已按 session metadata 隔离，仍需并发集成验证；
- 构建脚本已改用 `go mod verify` 与 `-mod=readonly`，仍需 CI 验证；
- i18n 资源加载但页面未真正使用；
- ruleset 索引已持久化，但更新包仍没有发布者签名；
- 跨层、迁移和跨平台产物验证仍不足。

## 3. 当前发布前问题

### P0-01：updater 替换阶段完整回滚（Fixed，需运行验证）

现在会先解压到唯一 staging 目录并验证 payload，再把旧顶层条目移动到备份目录，逐项安装新 payload；替换中途失败会删除已安装条目并恢复备份。仍需在真实平台验证 rename 权限和异常路径。

### P0-02：Windows core 孤儿进程检测（Fixed，需运行验证）

新增 `parent_death_windows.go`，通过父进程句柄等待退出，不再依赖 Windows 上不可靠的 PPID 变化。仍需 Windows 实机验证权限和快速退出边界。

### P0-03：macOS updater/架构发布（Mostly fixed，需运行验证）

`build_go.sh` 已构建 Darwin updater；release workflow 和 package 脚本已拆分 Intel/Apple Silicon 产物并强制检查 macOS updater。仍需 CI 验证实际架构。

### P0-04：跨层发布验证缺失（Needs verification）

当前有 Go/Flutter 单元测试，但没有可靠覆盖 UI→gRPC→sing-box、Start/Stop 并发、迁移失败回滚和各平台产物内容。需要在完整工具链环境执行：

- Go modules 已完成 build/vet/test/race；
- Flutter analyze/test；
- Android APK/AAB 中各 ABI 的 `.so`；
- macOS/Windows/Linux 包内 core/updater 和架构；
- Windows 父进程监督行为。

## 4. 当前高优先级问题

### P1-01：Update Check/Download 会话绑定（Fixed，需运行验证）

`update.go` 已使用 metadata session ID 保存并消费独立 Check 结果，Download 不再读取单一共享槽位。Flutter client 已提供 session ID 生成和 metadata 发送。仍需集成测试覆盖并发和重试。

### P1-02：构建过程修改依赖文件（Fixed，需 CI 验证）

两个构建脚本已改用 `go mod verify` 与 `-mod=readonly`；依赖整理移出构建路径。

### P1-03：i18n 资源与 UI 使用脱节（Partial）

Home/Settings 已开始使用 `I18n.t`，locale provider 会同步更新；Routing/DNS/Profile/Connections 仍有大量硬编码。

**建议**：继续完成全页面迁移或统一采用 gen-l10n。

### P1-04：更新来源真实性不足（Partial）

ruleset manager 现通过 cacheDir/index.json 原子持久化注册索引，重启后可恢复；更新包虽有 SHA-256，但仍没有发布者签名/公钥固定。HTTPS 和 checksum 已解决传输与偶然损坏问题，但不等于来源认证。

**建议**：为 release 增加签名与公钥校验，并在 CI 生成 SBOM/provenance。

### P1-05：批量导入回滚不能恢复已覆盖旧文件（Fixed，需 Flutter 测试验证）

`saveProfiles()` 现在在批量写入前保存旧文件字节，失败时恢复被覆盖文件或删除新文件；新增了对应 Flutter 测试。仍需完整工具链运行。

## 6. 不应直接定性为已证实缺陷的项目

1. `DropdownButtonFormField(initialValue:)`、`Color.withValues` 与最低 Flutter SDK 的兼容性：需要实际最低版本构建验证。
2. 空字符串字段是否一定被 sing-box 拒绝：需要生成配置并运行 sing-box validate。
3. 明文 JSON 是否构成高危漏洞：当前 POSIX 权限和 token 鉴权已存在，应结合本机威胁模型定级。
4. 缺少 golangci-lint 是否等于代码不合格：这是工程化建议，不是功能故障。
5. 缺少签名不等于更新必然被劫持：应描述为供应链强化缺口。
