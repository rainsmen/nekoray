## 一、最重要结论（先看这里）

三份报告的**历史修复核对工作基本准确**，但它们共同遗漏了当前工作区新引入的一个**阻断级缺陷和一个高危缺陷**——两者都在本轮整改新增的 ruleset 索引持久化代码中：

| # | 严重度 | 问题 | 位置 |
|---|---|---|---|
| **F1** | 🔴 **Blocker** | `Download()` 同一函数内两次 `m.mu.Lock()`——sync.Mutex 不可重入，**每次成功的规则集下载都会永久死锁**，且毒化后续所有 List/Register/Path 操作。现有测试从未覆盖成功下载路径，所以测试全绿 | `go/grpc_server/core/ruleset/manager.go:277-278 与 :316-317`（本人已亲自核实源码） |
| **F2** | 🟠 High | `Register()` 完全无锁读写 `m.items` 并调用契约要求持锁的 `saveIndexLocked()`，与其他操作构成数据竞争，可产生交错损坏的 index.json | `manager.go:190-212`（已核实） |

**直接推论**：「当前状态版」§2 将"ruleset 索引持久化"列为 Fixed、「复核」§2.7 给出正面评价、"核验"将其标为 Fixed/Needs verification——三份都不成立。这不是"需要运行验证"的问题，静态即可判定死锁。**在 F1/F2 修复前，rule_set 更新功能整体不可用。**

### 2.2 三份一致的结论（本轮复核确认成立）

- 第一轮 P0/P1 大部分已实质修复（详见 §三）；
- i18n 为 Partial（home/settings 已接 `I18n.t`，routing/dns/connections 仍硬编码英文）；
- 发布签名/SBOM/provenance 缺失为 Confirmed 供应链强化缺口；
- 跨层集成验证缺失是当前最大的发布前不确定性；
- 旧报告中"API 兼容性必然编译失败"等表述确属过度断言，应改为 Needs verification。

### 2.3 分歧与瑕疵

1. **工具链声明存疑**：三份均称"临时提供 Go 1.22 工具链并完成 Go 测试"，但四个 module 的 go.mod 均 require `go 1.24.7`。Go 1.22 只能靠 GOTOOLCHAIN 自动下载 1.24.7 才能跑通——该声明要么不完整，要么测试并非在这些 go.mod 下执行。建议在报告中写明实际生效的 toolchain 版本。
2. **"Fixed/Needs verification" 边界被滥用**：F1 这种静态可判定死锁也被归入此类。正确的边界应该是：逻辑矛盾（死锁/不可重入/契约违反）静态判定；数值/时序行为才需要运行验证。
3. **三份均未发现 update 功能端到端断裂**（见 §四 N5）：Flutter 侧 `checkForUpdates/downloadUpdate` 零调用方，session 机制修好了却不可达——"库层已修"与"功能可用"再次混淆。
4. build-flutter.yml 触发分支仍不含 main（analyze/test 不跑主干合入后验证），三份均未提及。

## 五、综合结论与建议顺序

### 总体判断

项目经过四轮迭代，**第一轮评估的 9 项高严重度问题已全部或基本闭环**，主链路（拉起 core + token）、线格式契约、安全三连（ZipSlip/路径穿越/更新校验）、数据完整性（原子写/ID/回滚）均已落地且有测试。三份报告的历史梳理工作有价值，「核验」提出的报告规范（基线+状态+证据+验证方式四要素）值得沿用。

**但当前不具备合入/发布条件**，原因不是遗留旧账，而是最近一轮整改自身引入的 F1 死锁——它恰好落在"测试盲区"（成功下载路径无测试）里，三份报告全部漏检。这再次印证「核验」自己的观点：**每个"已修复"判定都必须附带针对性测试证据**。

### 建议行动顺序

1. 【必须】修复 F1（合并/拆分临界区）与 F2（Register 加锁）；**同时补两个会失败的测试**：ruleset 成功下载路径测试（立即暴露 F1）、Register/List 并发 `-race` 测试
2. 【必须】N1 加重定向跳数上限；N2 Fatalln 改 error 返回
3. 【强烈建议】N3 给 update 检查接一个 settings 入口 + provider，让整条链路可达；N4 错误态透出
4. 【排期】i18n 全页面迁移、发布签名/SBOM、golangci-lint、analyze/test 分支加 main、单一版本源
5. 【发布前】在完整工具链环境执行全量验证（Go build/vet/test -race、flutter analyze/test、四平台产物审计），并在报告中记录实际 toolchain 版本
