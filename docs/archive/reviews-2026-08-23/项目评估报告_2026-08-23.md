# nekoray 项目评估报告

> **评估日期**: 2026-08-23  
> **评估版本**: v5.0.0-beta.3 (`nekoray_version.txt:1`)  
> **评估范围**: 全量代码 + CI/CD + 文档 + 供应链  
> **评估形式**: 只读审计，未修改任何源码  
> **评估人**: OpenCode (Muse Spark)

---

## 执行摘要

nekoray v5.x 已完成从 C++/Qt 到 Flutter + Go(sing-box v1.13.19) 的彻底重构，架构清晰（Flutter 瘦客户端 + Go 厚核心 + gRPC 唯一通道），14 协议全链路打通，CI 已能产出 6 平台产物。**整体技术选型合理，代码质量中等偏上，但存在若干高危安全与可靠性缺陷，尚未达到生产发布标准。**

### 综合评分

| 维度 | 评分 | 评语 |
|------|------|------|
| 架构设计 | **B+** | 分层清晰、职责单一，Go Core 单一真相源正确；但 proto 设计、状态持久化、多 module 管理仍有欠缺 |
| 代码质量 | **B-** | Go/Flutter 均有重复代码、硬编码、吞错、废弃 API 使用；测试覆盖几乎为 0 |
| 安全性 | **C** | 依赖过时(CVE)、ZipSlip/路径穿越、明文存储、明文 gRPC token、产物无签名/SBOM |
| 可靠性 | **C+** | 竞态、锁粒度过大、非原子写入、ID 碰撞、发布流水线 `continue-on-error` 掩盖失败 |
| 可维护性 | **B** | 文档与实现已基本对齐但仍有滞后；强类型缺失(map[string]interface{} 泛滥)、模块边界模糊 |
| 工程化 | **C+** | CI 未 pin SHA、缺并发/超时/最小权限、可重现性差、pubspec.lock 未提交、go 版本碎片化 |
| 文档 | **B** | README/ARCHITECTURE 重写质量高；DECISIONS 滞后；缺 SECURITY/CONTRIBUTING/REUSE 合规头 |

**结论**: **不建议直接发布 v5.0.0 正式版**，建议按本报告 P0→P1→P2 顺序整改 1~2 周后复审。

## 一、严重问题 (Critical / P0 - 阻断发布)

### Go Core (8 项)

## 六、亮点与肯定
